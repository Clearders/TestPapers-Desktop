# Local-first workspace implementation

CLE-24 through CLE-28 turn the Tauri shell into an offline authoring runtime. The accepted platform boundary remains unchanged: Vue calls versioned, command-specific Tauri IPC; the in-process Rust Local Engine owns SQLite, files, jobs, export, backup, and restore. No Local Engine HTTP listener or Python runtime is shipped.

## Runtime boundary

```text
Vue workspace UI
  -> application/useLocalWorkspace
    -> infrastructure/tauri/localEngineBridge
      -> allowlisted Tauri commands/events
        -> Engine supervisor
          -> LocalDataStore / JobCoordinator / workspace features
            -> SQLite + content-addressed blobs + backup archives
```

The main WebView never receives an absolute path. Native selectors return one-use selection IDs and display names; Rust retains and validates the paths. The sole Desktop workspace is protected by both Tauri single-instance activation and an OS advisory file lock.

## Data contract

`contracts/domain-model.lock.json` pins the accepted CLE-15 model used for the local projection. Stable IDs are canonical UUIDs generated by the creating runtime. Domain writes are versioned, content-hashed, appended to history, and guarded by base version/hash. Deletes and restores create newer semantic versions. Cloud-capable scopes also append a protocol-neutral candidate to `pending_mutations`; transport and conflict resolution remain owned by CLE-29.

SQLite upgrades are staged in a separate database, validated, and atomically swapped only after integrity and foreign-key checks pass. A database newer than the application is never downgraded or overwritten.

## Background work

Import, generation, export, and backup have independent FIFO workers. Each queue runs one job at a time and different queues may run concurrently. Restore and data-directory migration enter exclusive maintenance mode, cooperatively cancel active work, and leave current data untouched unless staging validation succeeds.

## Ported behavior

- CSV/JSON import normalization follows `Clearders/TestPapers` question import behavior. The Desktop implementation is independent Rust code protected by compatibility fixtures.
- Genetic paper generation and semantic DOCX/TeX output follow `Clearders/TestPaper-backend`. Binary ZIP metadata is not part of parity.
- PDF is produced from the local TeX artifact through a checksum-verified Tectonic sidecar invoked in untrusted, cache-only mode. The signed release pipeline must stage the reviewed platform binary and minimal `.ttb` bundle described in `src-tauri/resources/tectonic/README.md`; an unavailable or invalid payload produces a recoverable export error and never falls back to the network or a system executable.

## Security and recovery

Question images and other attachments are immutable SHA-256 addressed blobs. Workspace backups contain a SQLite online snapshot, referenced blobs, templates, and a hash manifest. Portable manual archives may use a passphrase; scheduled encrypted archives use an age identity stored in the OS credential store and require an exported recovery key. Restore rejects unsafe paths, hash mismatches, unsupported schemas, and incomplete workspaces before entering maintenance mode.
